# AGENTS.md

## Repository scope

This is the independent QuickExcel repository. Keep desktop, Core, infrastructure adapters, scripting, tests, documentation, and generated artifacts here. The sibling `../ExcelIO` is a separate repository containing the ExcelIO libraries. QuickExcel no longer depends on ExcelIO or ExcelIO.Formula; the sibling is not part of this repository. Do not edit, stage, commit, or copy sibling library sources as part of ordinary QuickExcel changes. Library changes require a separately scoped task.

## Build and verification

Run from this repository root on Windows x64 with .NET 10 SDK:

```powershell
dotnet build .\QuickExcel.slnx -c Release --artifacts-path .\artifacts\build -v minimal
dotnet test .\QuickExcel.Core.Test\QuickExcel.Core.Test.csproj -c Release --artifacts-path .\artifacts\build -v minimal
dotnet run --project .\QuickExcel.Scripting\smoke\QuickExcel.Scripting.Smoke.csproj -c Release --artifacts-path .\artifacts\build
.\scripts\build-quickexcel.ps1
```

Always supply `--artifacts-path` for managed builds, tests, runs, and publishes so all managed outputs stay inside QuickExcel. Native runtime build requirements and source provenance are in `QuickExcel.Scripting/native/SOURCES.md`.

Important! DO NOT run the full regression test suite for every feature change or bug fix! Only run the tests related to the modified areas!

Updating the local launch package is part of completing every feature change or bug fix. After the relevant targeted checks pass, automatically run `scripts/build-quickexcel.ps1 -SkipTests -RunSmoke` to publish and activate the latest self-contained Windows package before reporting completion. This is a standing user requirement; do not wait for another request or ask for confirmation. `-SkipTests` avoids repeating unrelated regression tests; the fresh package must still pass its production self-check. Verify that `artifacts/avalonia/active-windows.json` points to the new verified package used by `Start-QuickExcel.cmd`. A successful source build alone does not complete delivery. If publishing or self-check fails, preserve the previous active package and report the failure rather than claiming the local package was updated.

## Structure

- `QuickExcel.Core`: pure .NET domain model, document session, commands, history, facade and ports; no ExcelIO, WPF or native runtime references.
- `QuickExcel.Infrastructure`: typed XLSX/XLSQ v2 storage with v1 import/migration, typed workbook calculator with sparse dependencies and incremental evaluation and the isolated JSC worker/compiler factories. Current file support and limits are in `QuickExcel.Desktop/docs/09-m2-files-and-types.md`.
- `QuickExcel.Core.Test`: domain/session, typed storage, v1 migration and native scripting integration tests. File-format fixtures are constructed inline, including malformed ZIP/XML/JSON; keep prior v1 regressions.
- `QuickExcel.Scripting`: managed JSC bridge, native sources, and runtime smoke checks.
- `tools/QuickExcel.ApiGen`: generates the script declarations and capability manifest from the pinned Office Scripts API definition in `third_party/office-scripts-docs`; generated files must not be edited by hand, and CC BY 4.0 attribution must be preserved.
- `QuickExcel.Presentation`: UI-free editing controller, interaction/workspace rules and local file-dialog ports; depends only on Core and Grid.Shared.
- `QuickExcel.Grid.Shared`: UI-free sparse dimensions and range/merged-selection algorithms; original FastWpfGrid namespace and MIT provenance retained.
- `QuickExcel.Desktop`: product/architecture documentation and historical notices; the WPF project was removed in A7.
- `QuickExcel.Desktop.Avalonia` / `QuickExcel.Grid.Avalonia`: default host and native grid; use `scripts/test-avalonia-workspace.ps1 -Mode Workspace|Grid` for isolated UI checks and `scripts/test-avalonia-grid-benchmark.ps1` separately for raw scroll/drag/load samples. A3 contracts and evidence are in docs/64-avalonia-grid-and-workspace.md. The default launcher now selects the verified Avalonia package. Web/print contracts are in docs/65-avalonia-web-components.md; Windows publication/rollback is in docs/66-avalonia-windows-release.md. Physical verification is deferred per user; implementation status and limits are in docs/63-avalonia-implementation-log.md.
- `scripts/build-quickexcel.ps1`: test, publish and activate the self-contained Avalonia Windows package; `-RunSmoke -CreateArchive` validates the fresh package and creates a uniquely named ZIP plus SHA-256. `-OutputDirectory` must remain under this repository artifacts directory.
- `Start-QuickExcel.cmd`: launch the published app or build/run from source.

Keep `artifacts`, managed build caches, and native downloaded sources/build output out of Git. Preserve the native source version, SHA-256 verification, and license.

M3 syntax/binding/structure commands live in Core/Formulas and StructureCommands; WorkbookCalculator and TypedEvaluator live in Infrastructure/Calculation. The legacy storage adapters and LegacyWorkbookCalculator have been removed. Keep v1 file compatibility covered by independent ZIP/XML fixtures; calculation regressions use WorkbookCalculator. Current calculation/bridge/export limits are documented in QuickExcel.Desktop/docs/10-m3-calculation.md.

XLSX controlled formula preservation and rich text/link/note contracts are in QuickExcel.Desktop/docs/35-xlsx-preserved-formulas.md and docs/36-xlsx-rich-text-links-and-notes.md. Unmodeled formula semantics require the existing read-only/original-package path; old caches are never fresh results. Rich text replacement requires explicit flattening, and whole-cell font commands preserve inherited run fonts. Links are inert and note-only VML remains opaque. Structure/clipboard changes must implement attachment/reference rules before relaxing the existing guards; do not silently drop runs, links, notes, or unknown-content diagnostics.

M4 worker contracts live in QuickExcel.ScriptContracts (BCL only), the executable in QuickExcel.ScriptWorker, and the host client/Job in Infrastructure/Scripting. Desktop uses ScriptWorkerRuntimeFactory and ScriptWorkerActionExecutor without in-process fallback. scripts/ScriptWorker.targets copies the complete worker to build/publish output. QuickExcel.Core.Test/WorkerFixture is fault injection only and must never enter a release. Worker lifecycle evidence is in QuickExcel.Desktop/docs/11-m4-worker.md.

M4 package modules use file scriptApiVersion 3 and IPC protocol 10. File versions 1/2 may be opened for source inspection but cannot execute or save until explicitly rewritten as v3 or all scripts are removed; never silently migrate source. Function descriptor apiVersion 1/2 argument semantics remain independent of the file version. Imports resolve declared logical IDs only through the native in-memory ES module loader; preserve API v1 function naming and argument semantics (registration now uses host.functions.register). Module contracts are in QuickExcel.Desktop/docs/12-m4-modules.md. Actions require script-actions and workbook/actions bindings. The object API redesign in docs/79-script-api-redesign.md supersedes docs/76: scripts see `main(workbook, host)` with a capability-gated `QuickExcel` handle model, `host.events.on`/`host.functions.register`, and no `$`/`quickExcel` globals, `snapshot`, `patch`, `actions.register` or event property handlers. The live transaction model in docs/76 remains authoritative: host-owned transactions support read-your-writes and commit through DocumentSession as one undoable transaction, with full workbook/file rollback on failure. Legacy snapshot/patch script APIs are removed; the Core transaction model remains. Windows API v3 uses separate persistent isolated workers/contexts for UDFs and for actions/events in each authorized workbook session (docs/77-udf-context-isolation-and-transaction-calculation.md); both contexts are reused across successful calls and calculation rounds, never rebuilt per UDF call. Formula value reads may calculate the private transaction draft without publishing it; failed, superseded or revoked contexts are discarded without replay. Console requests and Linux workers remain one-shot. Ordered UDF batching and the 16 MiB IPC/native bridge budget are in docs/14-m4-batching.md. On Windows, WorkerProcess/WorkerSandbox are the mandatory zero-capability AppContainer launch path for formulas and actions: suspended creation, token verification, explicit IPC handles, Job at process creation, private read-only payload, environment allowlist, and profile cleanup; no same-permission fallback. The development-only tools/QuickExcel.SandboxProbe (including its read-only administrator WFP collector) must never enter a release. Normal-user Windows execution is needed for profile integration tests; do not weaken isolation to accommodate restricted test runners. Local loopback/DNS evidence and remaining deployment/security work are in docs/15-m4-os-isolation-adr.md. Strict policy and the final M6 OS security gate remain pending.

WorkerSandboxLease owns durable per-user records and exclusive leases for crash recovery; never sweep unjournaled legacy temp/profile names by prefix, follow reparse points, or remove a live lease/Job. QuickExcel.Core.Test/SandboxHostFixture is test-only and must not be published. Recovery contracts and local deployment evidence (including the direct long-path EXE launch failure) are in docs/16-m4-recovery-and-deployment.md. scripts/test-deployment-matrix.ps1 mutates only unique installation copies under artifacts and preserves failed-case evidence; local read-only ACL tests are not actual Program Files or clean-machine validation.

M5 grid/input contracts and evidence are in QuickExcel.Desktop/docs/17-m5-grid-and-input.md. QuickExcel.Grid.Avalonia and the historical IGridSurface/FastGridSurface are view-only (main-grid migration and current evidence: QuickExcel.Desktop/docs/24-main-grid-migration.md); writes still go through EditorController and DocumentSession. QuickExcel.Presentation/Interaction contains UI-free rules consumed through project references by Desktop and Core.Test. Preserve explicit formula-paste policy, atomic paste/clear history, composition gating, and original-cell draft ownership. scripts/test-m5-grid.ps1 now requires an explicit archived WPF rollback package; current interaction/benchmark modes use scripts/test-avalonia-workspace.ps1 and scripts/test-avalonia-grid-benchmark.ps1; run benchmarks separately from tests, retain raw samples, and distinguish synthetic WPF composition from real OS IME verification. M5 and M6 quality gates are not closed by the first UI slice.

UI-004/UI-005 contracts and evidence are in docs/18-m5-structure-and-workspace.md under QuickExcel.Desktop. Core/PresentationCommands owns stable rectangular copy-semantics sorting, style patches, dimensions and sheet deletion. Filter state remains session-only and keyed by SheetId; workbook views, freeze/zoom and sheet visibility now persist under docs/33-xlsx-workbook-views.md (navigation does not mark dirty, view commands do); filtered paste must never silently map across hidden rows. Desktop saves use IVersionedWorkbookStorage/SaveChecked with an opened/saved content fingerprint. Recent-file settings and injected dialog choices must use isolated artifact paths in smoke tests. The Workspace mode in scripts/test-avalonia-workspace.ps1 verifies Avalonia handlers; archived WPF checks remain available through scripts/test-m5-grid.ps1; do not claim physical input or complete M6 concurrency/OS/performance gates from it.


A6 Linux isolation/trust/printing and independent platform status are in docs/67-avalonia-platforms.md. Linux x64 requires Landlock ABI >= 3, default-deny seccomp, a verified systemd user scope with 256 MiB memory/no swap/32 tasks/5-second lifetime, parent-death binding, private read-only payload and journaled leases. Never disable AppArmor or WebKit sandboxing, or add an in-process/same-permission fallback. Linux persistent trust uses Secret Service; unavailable protection permits only explicit one-time consent. macOS worker is not implemented and execution remains disabled; a bridge/bundle build is not evidence of supported isolation. PlatformSmoke/TestProbe are development-only and forbidden in releases.

A7 removed both WPF production projects and the WPF publishing script; docs/68-avalonia-retirement.md records the boundary. Preserve the archived package, `avalonia-wpf-baseline-20261102` tag, licenses and historical evidence. Core.Test/Fixtures/WorkbookPackageFixture.cs now owns the independent ZIP/XML fixture, with no desktop-linked source. Do not restore the old source build as a rollback mechanism. Physical IME/DPI/accessibility/printing/clean-device gates remain deferred, and Linux IME had no candidate window in the VM.

Script events and session virtual files are specified in QuickExcel.Desktop/docs/69-script-events-and-virtual-files.md. Preserve zero-capability isolation: //xlsq/, //temp/ and //mem/ are logical byte snapshots, never OS paths. Events share API v3 actions bindings/trust; validate and atomically commit file and cell patches. Temp/mem stay session-only; persistent files use the virtual-files feature and manifest hashes.

Event enum/property handlers and the debug console are specified in docs/72-event-api-and-console.md. Console commands are explicit, one-round JavaScript requests in the existing isolated action worker; never execute them in the browser or host, or load/authorize stored workbook modules implicitly. Data patches remain atomic and undoable; console source/binding/signature rewrites are rejected. Keep output/history bounded and session-only, composition gating, read-only and stale-result guards, and IPC failure-log validation (current version 10).

JSC / TypeScript migration is recorded in docs/70-jsc-typescript-migration-plan.md and docs/71-jsc-typescript-implementation-log.md. JSC is the sole production engine; no QuickJS build switch or in-process execution fallback. The in-process JscRuntimeFactory exists only in Core.Test. TypeScript 5.9.3 runs full check/emit in a separate zero-capability compiler worker (1 GiB process, 5 MiB JS stack, 5-second native / 6-second host deadline, concurrency 1 / queue 0). Execution remains 256 MiB process, 256 KiB JS stack, 1-second operation / 5-second round. JSC-MEM-001 (64 MiB total engine allocation hard cap) remains OPEN, explicitly deferred by the user and not a progression gate; never claim the process cap or GC threshold implements it. Required typescript-sources files save raw source and fixed options, not generated JS/maps. Keep API v1 semantics, pure-JS signature bytes and complete historical rollback packages. macOS scripting stays disabled and ships no native engine/worker.
