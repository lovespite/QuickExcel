# PDF.js text extraction change

QuickExcel modification, 2026-11-03, under the upstream Apache-2.0 license.
Upstream: `pdfjs-dist@6.5.438/build/pdf.worker.mjs`, SHA-256
`43710009ea26bfbcb615524946e46e3aaf8ad927514f5e465e8ff6d18044ffe9`.
The npm lock retains the package integrity; the build also requires this exact source hash.

Skia's PDF output wraps shaped clusters whose glyph-to-Unicode mapping is ambiguous in
inline `/Span << /ActualText ... >> BDC ... EMC`. For example, Noto CJK uses the same
glyph for U+6587 and U+2F42. Unmodified PDF.js ignores this replacement during text
extraction ([upstream issue 12237](https://github.com/mozilla/pdf.js/issues/12237)).
MuPDF extracts the original text correctly. Unicode normalization is not an equivalent
fix: a workbook can intentionally contain either character.

`patch-pdfjs.mjs` changes only `PartialEvaluator.getTextContent`. It tracks a bounded
stack of marked-content frames across streamed chunks and emits the outermost inline
ActualText exactly once using the existing bidi transformation and glyph position.
Unmarked text and page rendering are unchanged. Nested tags and split text items do
not duplicate replacement text. This addresses the single shaped-cluster spans emitted
by our Skia generator. It does not claim complete general-purpose tagged-PDF support,
named property resources, ActualText spanning form XObjects, or multiline replacement
selection geometry. QuickExcel only previews its own completed print-session PDFs.

The real-browser smoke includes an independent handwritten PDF with plain text,
distinct same-glyph Unicode characters, multiple-codepoint replacements, nested tags,
empty replacement and adjacent spans; it also exercises the actual text-layer copy
handler and Chinese search on the PDF generated by Skia. Upgrades must review the
patch and rerun Windows and WebKit checks. No source map, external URL or extra runtime
is introduced. The distributed license directory includes this modification notice.
