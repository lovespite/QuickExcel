# UDF 上下文隔离与事务内计算

2026-11-04。更新 76 中的运行契约。文件 `scriptApiVersion` 保持 2；IPC 为 9；原生桥 ABI 和 `JavaScriptCore/2.54.2/b95c91b1/qx-sync-2` 标识不变。本次没有修改引擎、放松沙箱或新增进程内回退。

## 两个持久上下文

Windows API v2 的每个授权工作簿按角色惰性创建两个独立零能力 AppContainer worker：

| 角色 | 加载入口 | 生命周期与状态 |
| --- | --- | --- |
| UDF | `formula-functions` 绑定入口及其可达依赖 | worker 和 JSC 上下文均跨调用、批次和计算轮复用 |
| actions/events | `actions` 绑定入口及其可达依赖 | 动作与事件共享自己的持久 worker、模块变量和闭包 |

不在每次 UDF 调用或每次重算时创建新上下文。两个角色的 `globalThis`、模块实例、闭包和注册表互不相通；共同 import 的模块分别实例化。同一源模块可以同时具有两种绑定，但它在两个上下文中独立初始化，且只注册当前角色允许的能力。仅属于另一角色且没有被 import 的入口不会初始化。

宿主 worker 池按工作簿会话、授权生命周期和角色区分；每个角色有独立的忙锁。IPC `loadWorkbook` 要求入口与单一角色绑定一致；`beginRound` 不允许更改角色。UDF worker 不能执行动作或建立 workbook model 通道，actions worker 不能接受公式调用。原生模块来源检查继续有效，改写同名全局属性不能伪造注册角色。

用户要求的纯函数契约是：UDF 仅从显式参数取得输入，不读写 workbook，不依赖动作/事件的全局状态。运行时阻止 UDF 调用工作簿对象 API；传入的 API v2 区域仍为只读值快照。**上下文隔离不等于证明任意 JavaScript 的纯净性**：UDF 自己的模块变量、闭包和全局变量仍会保留，也仍可被其代码修改。当前没有静态纯函数证明或每次调用堆回滚，因此继续使用保守计算和有序批处理，不因这次拆分新增 UDF 结果记忆化、并行调用或重排。测试中的计数器只用于证明上下文复用。

仅修改动作自己的 JS 变量不再使公式缓存失效。工作簿关闭、禁用、源码/绑定/签名变化、重新授权会释放或替换 worker；异常、取消、超时、失效请求与提交被拒绝继续丢弃相关执行状态，不自动重放。事务内计算也可能推进 UDF 自己的 JS 状态；失败时保守丢弃会话执行上下文，不能把任意 JS 堆当作可撤销数据。

控制台保持独立一轮执行，事务内计算也不会隐式加载工作簿存储的 UDF。API v1 保持原语义；Linux 保持逐轮 worker 和五秒 OS 生命周期；macOS 仍禁用脚本。本次 Windows 证据不代表其他平台验证。

## 动作内读取最新公式值

以下代码现可在同一动作中读取草稿内的 A2，其中 A2 为 `=A1*2`，也可以为已授权的 `=TWICE(A1)`：

```javascript
$.actions.register({name:"Add", description:"1"}, c => {
    const sheet = $.getActiveWorksheet();
    const cell = sheet.getCell("A1");
    cell.setValue(Number(cell.getValue()) + 1);
    console.log(sheet.getCell("A2").getValue());
});
```

值写入记录在宿主命令草稿中，并使本次事务的计算视图失效。`getValue/getValues` 需要公式值或可能成为数组溢出子格的空白时，使用既有计算器对草稿计算；若遇 UDF，宿主调用独立的公式 worker，动作 worker 等待模型回复，不重入它的 JSC。一次 `getValues` 在读取矩阵前完成必要计算，避免同一矩阵混合计算前后的溢出值。

计算结果应用到独立的私有视图；不修改正式文档、不创建历史、不派发 calculated/changed 事件，也不成为正式计算器的缓存复用来源。同一草稿版本的重复读取复用该视图；后续影响计算的写入使其失效。`getFormula` 只读公式文本，不触发重算。旧 `snapshot` 始终读取本轮开始时的数据。

正常计算与草稿计算共用结果校验和数组溢出应用逻辑。公式错误以类型化错误值返回；不可用函数、只读保留公式或受阻依赖的旧缓存仍不能充当当前结果。空白/溢出读取也不能绕过这一规则。

本次实现按需触发既有工作簿计算轮，**尚未增加仅计算读取目标依赖链的专用规划器**。包含 UDF 时仍保守计算；写入/读取频繁交替可能重复计算整个公式集合。动作完成后继续按既有流程提交输入并进行正式重算；纯函数在这两次计算中应给出一致结果。

所有写入、样式和虚拟文件仍在最后统一验证、一次提交、一次撤销；异常、超时、取消或用户编辑使旧请求过期时全部不提交。计算基础设施失败即使被 JS 尝试捕获也不能提交事务。模型回调异常会终止正在等待回复的动作 worker，避免收尾协议错误掩盖原始超时。

## 资源与性能范围

原有每 worker 256 MiB 进程上限、256 KiB JS 栈、单原生操作一秒、活动轮五秒和 16 MiB 协议/桥容量约束保留；事务内计算计入动作的原有期限，不给每次读取额外续期。两个角色各有冷启动与驻留成本，需要同时使用时会占用两个 worker。复用避免逐 UDF 创建进程/上下文，但本次不宣称已测得整体性能提升。JSC-MEM-001 仍 OPEN，未实现总引擎分配硬上限。
