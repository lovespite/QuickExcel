## 预先确定的性能口径

在第一次对照运行前固定：Release、相同稀疏 100,000 行 × 256 列快照、同一进程、同为 960 × 500 DIP 视口、100% 网格缩放。两次预热，导航及大选区各 20 次，20,000 格选区各 10 次。先 DataGrid，后 FastWpfGrid，串行运行；顺序效应及不同文字绘制路径属于局限。绑定为单次探索样本，不用它声称 p95 收益。

- FastWpfGrid 远距导航 p95 ≤ 100 ms，并且不慢于本次 DataGrid。
- 25,600,000 格范围选区 p95 ≤ 50 ms；只保留范围，不枚举所有地址。
- 100,000 行筛选计算 p95 ≤ 500 ms。
- 记录候选提取、筛选后导航、分配量、进程工作集、托管内存、GC 次数和原始样本。

计时终点是 Dispatcher ApplicationIdle（布局/绘制队列处理后），不表示物理输入到显示延迟。原始样本写入独立 artifacts/validation 目录。性能门槛通过也不足以默认切换。

## 第一批实现契约

每表一个显式 DataRegion，首行为标题，B3:F3 等数据标题格提供按钮；标题可为空或重复，条件按列地址保存。候选按 CellValue 精确键区分数字、文本、空白、空字符串、布尔和错误；同值不同格式仍是同一键，标签采用扫描到的第一个格式，不按显示字符串合并。候选搜索不改变未显示的选项；取消丢弃草稿。

不同列 AND；同列支持文本等于/包含/开头/结尾、数字比较、两个条件 AND/OR、日期起止。文本条件 ordinal-ignore-case；勾选值为精确类型和值匹配。日期只接受带支持的年月日格式的数值，按工作簿日期系统解释；1900 虚构闰日和无法转 DateTime 的序列不匹配真实日历条件。日期不按显示文本比较。

候选列表虚拟化，最多扫描 100,000 行；候选标签总量 8 Mi 字符，超限明确拒绝，不截断。计算同步完成，无后台结果竞态；打开的面板捕获不可变快照和区域身份，期间数据变化拒绝旧草稿。刷新按快照对象缓存行结果；公式结果过期时丢弃旧隐藏集合，界面显示“筛选待更新，暂显示全部行”，并阻止依赖该筛选的剪贴板/删除/样式操作。

排序最多 32 个有序键、总区域 20,000 格；保留原稳定类型次序及空白末尾。支持独立方向、ordinal 大小写、自定义文本序列（最多 256 项）、显式填充/字体 ARGB 色置顶或置底。自定义列表中未列出值位于列表后，按普通类型顺序比较。颜色只认显式样式，不含条件格式。无中文拼音/笔画/区域文化排序承诺。

2026-11-02 排序入口与“扩展列”：功能区升序/降序、列标题面板和多级排序对话框统一按 `SortPlanning` 解析真实记录范围。只选中一个单元格或整列时，按活动单元格向上下左右的连续数据块排序，不再要求先精确框选，也避免整列选区触发 20,000 格上限；多行选区保留行范围并向右左扩展有数据的相邻列（`SortRangeCommand.ExpandColumns`）。判键仍是用户所在/所选列，整条记录（内容、样式、公式及复制式行引用位移）一起移动。标题启发式仅在首行非空单元格全为文本、且第二行至少有一个数字/布尔/错误值时命中；单列或全文本块不猜标题，可在多级排序对话框勾选“首行为标题”覆盖。数据块超过 20,000 格、含合并/图片/批注/链接、分组、部分条件格式或表范围不完整时仍明确拒绝且不写入。排序前会先补算关键列的旧公式缓存，重算失败则取消排序并在状态栏说明。空白活动单元格不向外推断范围。

筛选下排序处理整个声明区域，手动隐藏记录也参与；首行标题除外，行高/手动隐藏留在地址上，公式使用已有复制位移语义。所有键的新鲜度、容量、几何限制和公式转换先验证，再一次提交；撤销/重做重新应用条件。筛选/冻结/区域仍为会话状态，打开文件复位，数据排序结果正常保存。

## 试验首轮状态与缺口（历史）

来源、.NET 10 移植、快照适配、范围选区和核心筛选排序已实现。FG-01 的来源与可构建部分完成，主工作区的 DataGrid 容器依赖抽离未完成；FG-02 已有筛选排序闭环和性能证据，但复杂样式与真实 OS IME 仍待验收；FG-03/04 未关闭。

候选网格保留原生 TextBox 输入上下文，编辑经 EditorController 提交，失败保留原地址草稿。通用控件禁用内置模型写入，Desktop 负责编辑。大选区使用互不重叠矩形；显式枚举超过 100,000 格拒绝。可见行映射预计算，绘制不扫描筛选条件。修复冻结行/列交叉区域漏画，绘制失效合并到 Render 优先级。

现有 DataGrid 的容器、尺寸拖动、图片等调用尚未全部抽象；候选复杂样式、合并/图片、尺寸事务、辅助技术和完整键盘功能尚未与默认网格对等。含合并/图片工作表明确拒绝进入试验网格；候选内禁用未接入文档事务的列宽拖动。真实 OS 中文输入及跨显示器 DPI 未验收。上述缺口决定当前不切换默认网格，M5/M6 门禁不变。

候选选区按可见行列投影，手动隐藏行列不进入选区；主界面的旧隐藏行剪贴板行为没有随之迁移，仍属功能对等差异。隐藏的首尾边界不能解释为行列标题；冻结/滚动索引分段二分映射，允许返回多个矩形，不把不连续领域地址压成连续写入。自定义行高命中采用实际尺寸，历史恢复时替换尺寸索引。标题同时显示筛选标志与最近排序方向/级别；排序标志表示上一次排序设置，不保证后续编辑后仍有序。

默认主界面使用方式：选中含标题的矩形 → 数据/筛选 → 点击数据标题格右侧按钮或 Alt+↓。条件确认后可继续筛选其他列；多级排序可在数据选项卡或标题面板打开。试验网格入口为视图/试验网格，编辑后关闭返回主界面保存。它共享当前文档的撤销事务，关闭时提交有效草稿，非法草稿阻止关闭；已关闭窗口不会执行排队刷新。

## 后续修正：默认启动包与已选中格拖选

默认目录 `artifacts/QuickExcel` 曾保留不含 `FilterHeaderAdorner` / `EstablishDataRegion` 的旧程序集，而启动脚本优先打开此目录，因此从默认入口看不到新表头筛选。修正后使用 `scripts/build-quickexcel.ps1 -SkipTests` 同步默认目录，保留既有启动路径。

## 后续修正：试验网格筛选越界与拖选卡顿

两行小表筛选后，视口中的表格下方空白仍被命中为单元格；隐藏行投影将越界可见索引转换为 `-1`，选区通知随后可能让输入框访问非法领域行。可见数量曾使用原始 Count 并多包含一行，刷新当前格也曾按原始行列数截断。现在命中、可见数量、位置映射与当前格均按可见行列边界约束，表格外空白不会成为地址。新增回归在修复前失败，证据为 `artifacts/validation/m5-grid/20261029-052232-9e48c243/DataOperations`。

拖选跳过同格内重复移动，保留上一绘制选区并只重绘成员变化及当前格/悬停行；输入框准备与焦点恢复延后到鼠标捕获结束，丢失捕获停止拖选计时器。额外诊断发现 WPF 位图锁曾等待 100–200 ms（临时诊断原始数据在 `artifacts/validation/fast-grid-fix-20261029/render-profile.csv`，诊断代码已移除）。绘制改用零等待 TryLock，忙时合并最新状态并在 16 ms 后重试；拖动自动滚动避免同步位图复制。卸载停止重试，重新加载触发重绘。

专项规则测试 20 项通过：`artifacts/validation/fast-grid-fix-20261029/grid-fixes.trx`。WPF 专项 47 项通过：`artifacts/validation/m5-grid/20261029-053354-64983cbb/DataOperations`，包括两行表筛掉最后一行、冻结仅余标题、清除筛选恢复地址、同格 100 次移动无重复工作、多次排队拖选保留最终状态、筛选与冻结交叉拖选，以及局部/完整重绘像素一致性。不运行全量回归。

Windows Computer Use 在临时空白工作簿验证 A1:D5 拖选得到 20 格，列头面板取消空白候选后隐藏第 2–5 行并将当前格移到 D1；继续拖至 D8 得到 16 个可见格，无 row 异常，释放后输入框恢复焦点。该注入鼠标路径不等同于物理设备延迟测试。

独立性能样本 `artifacts/validation/m5-grid/20261029-053244-0a1437f7/FastGridBenchmark`：拖选步骤 p50/p95 为 0.25/0.89 ms，同格 100 次移动为 0.045/0.063 ms，25,600,000 格选择为 0.80/1.22 ms。拖选预算在运行前设为 p95 ≤ 50 ms；计时现在等待 Dispatcher 空闲及位图重试完成，`inputRaw` 单独记录同步选区/悬停处理时间，均不代表实际显示器呈现延迟。远距导航 p95 为 216.99 ms，未达到原 100 ms 门槛，因此整体 `passed` 仍为 false，不宣称全部性能预算通过。保留先前失败样本 `20261029-052509-e9848649`、诊断样本 `20261029-053005-05467110`；不从不同轮次推导稳定倍速。

## 持续大范围框选：绘制与合成解耦

2026-10-29 后续定位：上面的紧密循环测试在 Dispatcher 空闲后立即执行下一步，未充分覆盖合成线程正在消费位图时的持续拖选。新增 `FastGridDragBenchmark`，1400×850 DIP 窗口，100,000×256 显示范围，前 300×40 格填充文字；每步先等待 16 ms，5 次预热、60 个样本。分别测同步选区处理和到位图绘制完成的耗时，预设每场景绘制 p95 ≤ 50 ms，并记录原始样本、分配量、GC 和进程 private bytes。后面三轮重复在视口内拖选，检查持续绘制与内存情况。

修复前同一测试复现：输入 p95 为 0.03–0.47 ms，绘制却为 103–199 ms。原 `_drawBuffer` 同时作为可修改画布和 `Image.Source`；零等待 `TryLock` 虽避免同步阻塞，合成线程占用期间的重试仍让选区画面延后。选区没有逐格枚举，耗时主要发生在共享位图的呈现同步。

现在 `_drawBuffer` 只供软件绘制，完成后复制当前视口为冻结的 `BitmapSource` 交给 WPF，后续输入不会修改合成线程正在使用的帧。保留局部重绘和排队合并；可见像素没有变化时复用上一帧。删除共享位图重试计时器。斜向自动滚动同时更新两轴后仅提交一次选区，修复原来第二次更新使用旧鼠标行号、使选区回缩的问题。

| 纵向自动滚动框选 | 102.62 | 15.92 |

## 边缘自动滚动：像素位移与可见内容缓存

用户确认可见区域内与边缘自动滚动都有卡顿，继续处理上一节未解决的滚动路径。旧路径按 50 ms 计时器整行/整列推进，并在拖动时每步重画整个视口；相同格数移动的专项对照仍有每 65 步 34–39 次 Gen2。仅把计时器改为 16 ms 不够，Windows 上实测调用间隔仍常为 25–32 ms；单用 WPF Rendering 回调又会在受遮挡的测试窗口中降频。因此最终采用有共享限速的 Rendering 回调加 16 ms 兜底计时器。

`UseSmoothScrolling` 与选区覆盖层一起由 Desktop 显式启用：

- 自动滚动按实际经过时间累计像素位移，靠边基础速度为 360 DIP/s，指针越过边缘越远可加速至 1080 DIP/s；单步最多累计 50 ms，避免 UI 停顿后的追赶式跳跃。每次更新至少相隔 16 ms，两种调度源不会重复推进。
- 文字仍使用原来的栅格绘制与字形缓存，每格生成小型不可变图像；已有可见格复用，只补新进入视口或失效的格。视口使用 `DrawingImage` 组合，不再每次分配整张视口快照。缓存仅保留当前视口，超大格先裁剪再分配。其他宿主默认仍使用原位图路径。
- 滚动偏移统一用于内容、选区、命中测试和宿主几何。冻结/滚动四个象限分别裁剪，部分可见的首尾单元格保留正确领域地址。释放捕获与卸载都会停止计时器并解除 Rendering 订阅。
- 快速拖出视口时立即将选区终点约束到可见边缘，不等待首个滚动回调；修复“越界后马上松开，选区仍停在原格”的情况。
