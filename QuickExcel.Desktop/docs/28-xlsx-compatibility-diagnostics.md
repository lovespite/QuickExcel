## 1. 分类与保存契约

Core 的 `CompatibilityDiagnostic` 包含稳定 Code、Kind、Feature、说明、部件、工作表名和范围；不引用 WPF、ExcelIO 或原生运行时。`WorkbookFileState.CompatibilityDiagnostics` 记录导入时的文件特性，`TypedWorkbookStorage.InspectCompatibility` 检查当前快照。

| 分类 | 当前范围 | 保存影响 |
| --- | --- | --- |
| 可编辑（已支持子集） | 说明已有模型的编辑能力，单独汇总公式/缓存数量 | 不表示整个文件可无损写回，也不证明公式计算正确 |
| 仅保留 | 未建模样式、主题关联、页面、视图、属性、关系等；工作簿仍与导入模型一致 | 普通 XLSQ 保存继续原样保留内嵌 XLSX 字节；导出另有损失检查 |
| 内置不可计算／待验证 | 当前公式中的非内置函数、解析或名称绑定失败 | 与格式损失独立；本轮不把此项加入旧保存损失列表，也不改变重算行为 |
| 潜在损失 | 内容已改变时，原文件中的未建模特性 | 继续阻止普通保存，须明确另存受支持副本 |
| 拒绝 | 数组等非 normal/shared 公式、无法安全展开的共享公式 | 保持导入拒绝，增加部件/工作表/公式范围，不创建可编辑文档 |

原有 `CompatibilityIssues` 及 `SaveIssues` 继续承担保存/导出损失门禁。结构化诊断不通过过滤分类来绕过保护。唯一减少的重复提示是同一外部关系原先同时出现的“外部关系”和“未建模关系”；仍保留外部关系损失记录，且不访问外部目标。重开保留副本重新构造同样的诊断，不新增 XLSQ 持久化字段或版本。

文件特性位置是**导入时位置**，不会因改名/结构操作误称为当前定位；公式位置从当前快照读取。插入、改名、撤销后再次打开报告重新检查。撤销恢复内容一致时，潜在损失回到仅保留，并恢复原包不变保存路径。

## 2. 公式与界面

- 使用已有 `FormulaSyntax`、`FormulaBinding` 和 `StandardFunctions.Signatures`，不维护另一份函数白名单。检查名称展开后的函数；字符串中的函数名不会被误报。
- `_xlfn.XLOOKUP` 等保留原始源码和缓存，报告内置计算器不支持。用户脚本函数同样标为待验证，并明确注册/显式启用的条件；检查不执行模块、加载运行时或授予脚本权限。
- 缓存保留 stale 状态；有旧缓存、无缓存、已有当前计算结果分别说明。检查不把缓存标新鲜，不改变计算结果。修改或替换公式后，报告不会残留已删除公式的问题。
- “文件 → 兼容性报告”按五类分组，显示特性与定位；导入拒绝在打开错误中显示。检查使用后台任务和现有停止入口，避免在 UI 线程扫描所有公式。打开含公式文件时增加简短缓存说明。
- 没有潜在格式损失时不显示“须另存受支持副本”，避免把公式能力提醒混同为格式损失拦截。
- 文件特性最多列出 1024 个位置，超过后明确提示定位省略；已有 1024 种独立损失说明的拒绝预算保持。公式问题最多列出 1024 个位置，达到上限后明确说明后续公式未逐项检查。数量汇总仍覆盖所有单元格，不把省略理解为支持。

## 4. 未完成范围与下一步

XC-0003 暂不整体勾选：共享字符串/共享样式等部件还没有展开到所有受影响单元格；不是所有导入/命令拒绝都已结构化。没有运行脚本来判定 UDF 是否已注册，没有传播所有不可计算依赖，也没有新增未知公式的只读/受限编辑规则。这些风险继续由既有门禁和 XC-0106 承接。

本轮没有减少真实特性的损失警告，没有复制未知部件，没有新增通用 XLSX 保存。E0 的真实 Excel 样本、版本/build、重开/重算及预期差异判定仍缺，E0/E1 不关闭。下一轮可使用本报告推进 E1 的 P0 样式继承（XC-0102）与白名单元数据/保存路径（XC-0103）；数字格式（XC-0101）按既定子集逐项补齐，并持续扩充 E0 夹具。
