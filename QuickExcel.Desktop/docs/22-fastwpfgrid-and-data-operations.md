## 1. 选择方向与依据

QuickExcel 已有稀疏不可变工作簿、类型化计算、存储、命令及历史体系。FastWpfGrid 的按地址读取模型、可见区域绘制、冻结与鼠标交互基础，适合承担显示层；收益来自减少单元格容器和模板布局开销。首批同环境视图对照已有证据，完整矩阵仍待验证，Core 命令执行和计算开销须单独测量。

2026-10-29 对上游源码的检查发现：

| 上游基础 | 对本项目的意义 | 必须补齐的部分 |
| --- | --- | --- |
| `IFastGridModel.GetCell(view, row, column)` 按地址取内容 | 可映射到现有快照，避免再建完整可变工作簿 | 显示值、编辑原值、样式及版本一致性适配 |
| 可见区域位图绘制、冻结区域和局部失效 | 可复用绘制与滚动基础 | 高 DPI、复杂字体、缓存边界及实际帧延迟验证 |
| 表头内容、列头点击和单元格命令入口 | 可实现筛选入口和状态标记 | 数据区域标题行按钮、弹出面板、键盘与焦点规则 |
| 隐藏行/列及模型坐标映射 | 可承载筛选结果 | 手动隐藏与筛选隐藏分离、索引更新和地址一致性 |
| 逐单元格 `HashSet` 选区及范围枚举 | 现有选区机制不能直接作为大范围选择方案 | 改为范围表示，避免拖选成本随选中格数增长 |
| 原工程目标为 .NET Framework 4.5 | 需要现代化移植 | .NET 10 SDK 工程、依赖审核、DPI 与输入生命周期 |

原仓库采用 MIT 许可证；不同派生仓库不能假定许可证相同。本仓库已建立 `QuickExcel.Grid.Wpf` 项目，锁定上游 `8bcfaf37df343e0b7ccffb3718d9a973a1f58b40`，保留版权与许可证。内嵌 WriteableBitmapEx 的版本身份、许可证和本地修改见 [来源清单](../../QuickExcel.Grid.Wpf/SOURCES.md)。下方 `master` 链接保留为初始评估参考，实际构建来源以固定提交清单为准。

## 2. 架构与职责

以下职责已在主网格迁移中接入；旧 DataGrid 容器依赖已移除，后续能力继续遵守相同边界。

| 层次 | 职责 | 依赖边界 |
| --- | --- | --- |
| `QuickExcel.Grid.Wpf` | 绘制、几何与命中测试、滚动、范围选区、冻结、编辑器定位、输入事件 | 保持通用 WPF 控件职责，不引用 Infrastructure、ExcelIO 或脚本运行时 |
| Desktop / `FastGridSurface` | 实现网格适配，投影 `WorkbookSnapshot`、样式和工作区状态，转发用户操作 | 接入 `IGridSurface`、`EditorController` |
| Desktop 的无 WPF 工作区规则 | 数据区域、筛选条件、候选值、可见行映射、筛选请求身份 | 首期按 `SheetId` 保存会话视图；可在 Core.Test 中验证 |
| Core 命令与 `DocumentSession` | 排序计划验证、数据与公式变更、原子提交、历史、修订通知 | 纯 .NET，保持唯一文档写入入口 |
| Infrastructure | 既有计算和存储；未来经明确契约支持筛选状态持久化 | 不承担控件选区、焦点和绘制 |

读取链路为“已提交快照 → 视图投影 → 网格”；写入链路为“用户意图 → EditorController → DocumentSession → 新快照 → 刷新”。控件不能绕过会话直接修改工作簿，也不另建一套公式计算或文档撤销栈。

[`IGridSurface`](../Controls/Grid/GridSurface.cs) 已提供范围选区及编辑生命周期入口，`FastGridSurface` 负责当前格、几何、视口和尺寸预览适配。范围选择不枚举整个大选区；需要显式枚举、复制或修改时分别执行容量检查。冻结、图片和输入不再访问旧 DataGrid 容器，具体契约见 [主网格迁移](24-main-grid-migration.md)。

| 项目 | 目标行为 |

## 4. Excel 式列头筛选

### 4.1 数据区域与标题行

筛选按钮应附着在数据区域的标题单元格，例如 B3:F3，而非只支持窗口顶端 A/B/C 列标。建议引入工作区级 `DataRegion`，包含区域身份、`SheetId`、矩形范围、是否含标题行及按列保存的条件。

首期明确选择并建立数据区域，默认一个工作表一个活动筛选区域；不以空白格启发式静默扩展范围。标题文本可为空或重复，内部列身份应使用区域与逻辑列地址，不能直接用标题文字作键。多个独立区域、完整 Excel Table 对象及结构化引用属于后续独立设计，不能因已有 `DataRegion` 就宣称支持。

### 4.2 必做功能

| 功能 | 目标 |
| --- | --- |
| 下拉入口 | 显示未筛选/已筛选状态，升降序及多级排序标记；支持鼠标、键盘和焦点返回 |
| 候选值列表 | 搜索、复选、多选、全选、空白项、清除此列、清除全部；高基数列表虚拟化 |
| 多列组合 | 不同列条件以 AND 组合；修改一列保留其他列条件 |
| 同列条件 | 文本等于/包含等、数值比较/区间、日期范围；支持两条件 AND/OR |
| 候选值联动 | 基于其他列的条件生成本列候选值，同时保留本列已有选择，允许修改或取消本列条件 |
| 操作预览 | 面板中的选择属于临时草稿，确定才应用，取消不改变视图；搜索不能悄悄清空未显示的已选项 |
| 行为一致性 | 筛选隐藏整条工作表行，保留原地址和领域数据；清除筛选后恢复手动隐藏状态 |

空白单元格、空字符串、数字、数字文本、布尔值、日期显示和错误值分别定义判定规则。日期条件需结合数字值、日期系统和格式解释；禁止仅比较格式化字符串。候选标签可能相同而底层值不同，应单独保存稳定的匹配键，并明确是否按显示标签分组及该组匹配的值集合。

公式筛选需要结果新鲜度策略；关键结果缺失或过期时明确阻止应用或要求完成重算，不静默使用旧缓存。重算或编辑改变依赖列后，须使筛选结果失效或提供重新应用状态，不能继续把旧索引冒充当前结果。

### 4.3 UI 与计算分离

网格只绘制按钮并返回按钮对应单元格及屏幕几何。搜索框、虚拟化勾选列表和条件编辑使用原生 WPF 弹出面板；处理滚动、冻结、缩放、窗口边缘、焦点恢复、IME 和键盘关闭。已有图像命令入口是扩展基础，不等于现成的 Excel 筛选组件。

筛选条件变化时生成可见行映射；滚动和绘制查询映射，不逐帧扫描整张表。手动隐藏、筛选隐藏和冻结分别建模后组合，避免清除筛选意外显示原本手动隐藏的行。区域外记录不参与筛选判定；同一工作表行一旦隐藏，其区域外单元格也随行不可见。

若后台计算候选值或可见行，绑定会话、工作表、快照/计算结果版本和筛选请求代次。新请求取消旧请求，发布时再检查身份；旧任务不能覆盖后来输入、切表或重算产生的结果。

## 5. 高级排序

### 5.1 能力与现状

目标包括多关键列、独立升降序、增加/删除/调整层级、标题行排除、稳定排序，以及可扩展的自定义顺序、大小写、填充色和字体色规则。例如“部门升序 → 金额降序 → 日期升序”。这些能力分阶段交付，排序规则的数据结构在首期就应支持多个有序键。

实施前的 [`SortRangeCommand`](../../QuickExcel.Core/PresentationCommands.cs) 仅支持单关键列、20,000 格上限，`SheetViewState` 为单列显示文本包含筛选。现已增加不可变多键描述和类型化多列条件；显式 DataRegion 允许对全部记录排序后重算筛选，旧筛选入口仍保留拒绝策略以维护历史回归。容量、类型顺序和引用契约没有放宽。

拟议 `SortDescriptor` 包含数据区域、表头规则及有序 `SortKey` 列表；每个键包含逻辑列、排序依据、方向和必要比较选项。旧单列入口映射到单键描述，保留既有默认行为。多键比较全部相等时保持原相对顺序。

### 5.2 数据与事务语义

- 从某个列头发起排序，移动声明的数据矩形内完整记录及其样式，不能只移动当前列造成字段错位；区域外单元格不随意移动。
- 标题行不参与数据排序。未建立区域且范围有歧义时，要求用户明确区域；不能默默扩大现有选区。
- 复用现有公式复制位移语义：移动记录中的相对行引用调整，绝对行引用保留，区域外公式及名称保留原地址。该语义须以回归验证，不宣称完整 Excel 引用兼容。
- 所有排序关键列的公式缓存都须通过新鲜度检查。内容、样式、公式变换及容量统一预检，再经 `DocumentSession` 一次提交、一次撤销。
- 行高与手动隐藏等行元数据是否随记录移动须明确。首期保持现有排序的“元数据留在地址上”契约；改变行为应另行设计和测试。
- 有合并、图片或不支持几何的区域继续遵守现有拒绝策略。只有锚点和合并变换语义完成并有证据后，才扩大允许范围。
- 数字文本、空白、空字符串、错误、日期和混合类型须有明确顺序；旧默认数字/文本等类型次序及空白置后规则不能被无意改变。

自定义列表、大小写和颜色排序属于目标扩展；中文拼音/笔画、区域文化排序、条件格式图标和颜色需独立定义支持矩阵与对照样本。不能把 ordinal 文本比较宣称为 Excel 中文排序，也不能在未实现条件格式求值时承诺按其最终显示颜色排序。

### 5.3 筛选后的排序

**必须验证筛选和排序共同使用的路径。** 建议首期契约为“对明确数据区域的全部数据记录排序，再在新快照上重新应用筛选条件”，并在界面说明筛选隐藏记录会参与排序。手动隐藏行的参与规则、冻结与选区恢复也须在实现前冻结为明确契约；不按控件当前呈现顺序隐式决定。

排序前提交有效草稿，组合输入或非法草稿阻止操作。完成后将筛选索引绑定到新快照；撤销/重做后重新求值，避免新数据搭配旧可见行。原子排序与视图刷新之间应有明确忙碌/待更新状态。

该契约已在显式 DataRegion 路径落地：筛选下对完整声明区域排序，再重新应用条件；无明确区域的旧筛选路径仍拒绝排序。过滤后的复制、删除与样式操作继续遵守现有可见行规则；粘贴目标包含筛选隐藏行时整批拒绝，不能静默压缩映射。

## 6. 容量、性能与持久化

### 6.1 大数据处理

- 显示层目标沿用 UI 的 100,000 行 × 256 列及稀疏工作负载，不建立全矩形单元格对象。
- 首次筛选可能需要扫描范围；候选值提取、多个条件的索引组合、局部失效和缓存预算分别测量，不能只测绘制速度。
- 高基数候选列表采用虚拟化、搜索和有界缓存；如果分页或限制候选数量，必须说明范围，不能静默截断并造成错误筛选。
- 多键排序预先提取键并计算行排列；比较过程中不反复格式化文本或执行公式。提交成本、历史占用和 UI 刷新分别计时。
- 现有排序上限 20,000 格、历史预算及单次编辑限制继续有效。验证十万行筛选不代表支持十万行事务排序；扩大排序容量必须另测预检、取消、内存与历史成本，不能直接删除限制。
- 位图绘制不自动保证更快；高 DPI、长中文、换行、字体变化、图片和大选区都纳入测量。

### 6.2 状态保存

首期筛选与冻结继续按 `SheetId` 保存为会话视图，不产生文档 dirty，也不写入文件；排序后的数据由现有保存链路持久化。筛选条件的会话操作不冒充文档历史，排序本身必须可撤销。

筛选/排序持久化现已列入 [XLSX / Excel 对齐计划](26-excel-compatibility-roadmap.md) 的 XC-0301，仍为待实现项。须扩展领域元数据、XLSQ/XLSX 存储支持矩阵、兼容性报告与往返测试，不由控件自行序列化，也不默认修改同级 ExcelIO 仓库。现有未支持文件特性的保留/拒绝/另存规则继续适用。

## 7. 分阶段实施与退出条件

以下编号保留原定工作与退出条件。FG-01 的来源、移植和 DataGrid 依赖抽离已完成；FG-02/03 的当前功能子集已实现并有专项证据，真实 IME/DPI/辅助功能矩阵仍待验收；FG-04 的默认切换已于 2026-10-29 完成，完整性能与交互退出条件继续单独跟踪，不再把“是否切换默认网格”列为待办。

| 阶段 | 工作 | 退出条件 |
| --- | --- | --- |
| FG-01 来源与移植 | 锁定提交和许可证，建立 .NET 10 项目及快照适配，抽离 DataGrid 依赖 | 可重复构建；按需读取；控件不直接写文档；来源清单完整 |
| FG-02 关键原型 | 范围选区、原生编辑/IME、复杂样式绘制；标题行筛选、多列条件和多级排序闭环 | 本节必验场景通过；有可比较性能样本和真实 IME 证据；不存在破坏性映射错误 |
| FG-03 功能对等与扩展 | 尺寸、冻结、剪贴板、合并/图片、公式栏、键盘、无障碍；补齐筛选面板及高级排序目标规则 | 相关领域、WPF、保存往返与实机验收通过；明确高级能力和容量支持矩阵 |
| FG-04 默认切换 | 对照当前 DataGrid 候选，完成缺口与迁移，记录采用结论 | 固定环境下达到预先约定的性能预算，必要交互无退化；更新 ADR、说明和证据 |

FG-02 必须执行的用户场景：

1. 在 B3:F3 建立标题行，下面包含部门、金额、日期等数据；保留区域外数据、手动隐藏行和部分公式。
2. 从标题单元格下拉框按“部门＋金额区间”联合筛选，验证候选值联动、搜索、取消、清除此列及清除全部。
3. 保持筛选，按“部门升序＋金额降序”执行两级排序，验证表头、完整记录、隐藏行、公式与样式。
4. 撤销/重做后核对数据和筛选可见行，保存重开核对排序结果；首期筛选状态按会话契约复位。
5. 在冻结、横向滚动、缩放及系统中文输入下重复入口和编辑操作，检查按钮定位、焦点与原格草稿。
6. 同时覆盖现有上限内排序、超限明确拒绝、十万逻辑行筛选和大选区；不能用缩小数据掩盖容量边界。

如果 FG-02 无法在合理改造范围内满足输入、筛选排序或性能要求，重新评估采用 FastWpfGrid 的范围；不能为保留候选控件而放弃必做功能。

## 8. 验证与证据

| 验证层 | 重点 |
| --- | --- |
| 无 WPF 规则与 Core | 范围选区、坐标映射、多列条件组合、候选值联动、类型边界、多键稳定性、公式新鲜度、引用位移、原子失败和撤销 |
| 实际 WPF 控件 | 标题行按钮、弹出层位置、虚拟化列表、键盘/焦点、冻结与筛选组合、尺寸预览、合并图片和 DPI 绘制 |
| 真实系统输入 | 中文候选、组合期间保存/切表门禁、确认/取消后的草稿与焦点；合成事件不替代 OS IME 验证 |
| 文件与会话 | 排序保存重开、筛选会话生命周期、后台结果过期/取消、关闭后返回和外部修改冲突 |
| 性能 | 绑定、连续滚动、远距跳转、大范围拖选、筛选面板打开、候选搜索、筛选计算、多级排序、命令提交与绘制分段 |

迁移前 DataGrid 对照保留在 23 号历史记录；当前基准只测 FastGrid，旧对照代码已移除。后续比较须固定数据生成器、Release 构建、硬件、窗口、缩放及预热/样本口径，保留原始样本、p50/p95、内存、GC 和二进制身份。历史版本数据不直接当作本版基线。必须区分 Dispatcher 布局空闲、渲染帧与物理输入到显示的测量终点。

性能预算在运行对照实验前确定并记录，不能观察结果后移动标准。基准与测试串行且分别运行，证据保存在本仓库 `artifacts/validation` 下唯一目录。仅运行改动相关的领域测试和交互模式，不为每个切片运行全量回归；托管构建/测试/运行始终提供 `--artifacts-path`。新增测试模式的名称和命令由实施记录给出，本文不列出尚不存在的脚本入口。

主网格迁移后的 Interaction、Workspace、Ribbon、Product、DataOperations 和 GridIntegration 已有通过记录，见 [当前证据](24-main-grid-migration.md)。23 号记录中的早期交互失败按历史保留；新主网格真实 OS IME、跨屏 DPI、完整辅助功能及 M5/M6 门禁仍未关闭。

## 9. 实施前需冻结的细节

- 采用的上游提交、依赖版本和本地派生代码维护范围。
- 表头缺失/重复、候选值同标签不同值、混合类型与日期分组的精确行为。
- 筛选下排序时手动隐藏行、选区、冻结与元数据的参与和恢复规则。
- 自定义列表、文化/大小写、颜色排序的首批支持矩阵；Excel 特有边界行为用固定样本对照。
- 大规模筛选与排序预算、候选列表容量、取消和历史超限策略。
- 筛选/排序配置跨文件保存是否进入后续里程碑，以及对应格式契约。
