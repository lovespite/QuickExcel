# QuickExcel 架构决策记录

日期：2026-10-22。本记录解释目标方案的依据、代价及重新评估条件。**已选方向**表示后续实现应遵循的设计，并不代表相关功能已经落地；**待验证**必须在指定里程碑以实验或兼容性证据收敛。当前事实与实施状态以 [文档首页](README.md) 为准。

## ADR-001：Windows 优先，WPF 作为首个桌面界面

**状态：已选方向；当前原型已采用。**

沿用 C#/.NET 与现有 WPF 原型，优先打通本地文件、键盘编辑、撤销和脚本工作流。领域与应用层不依赖 WPF，后续跨平台可以替换呈现层，不因未来可能跨平台而现在重写所有基础能力。

代价是首个 Beta 仅支持 Windows x64。跨平台不是本阶段的验收条件。若目标用户或分发渠道明确需要 macOS/Linux，再独立评估 Avalonia 等界面方案；不能把仅编译领域层视作已经支持另一个操作系统。

## ADR-002：ExcelIO 保持独立，编辑器使用带类型的领域模型

**状态：M1 内存模型已接入；M2 文件类型保真待实施。**

现有 `XlCell.Value` 以字符串为主，不足以区分文本、数值、布尔、错误和空白。新文档模型使用显式 `CellValue`，将输入内容、公式计算结果和显示文本分开。日期以 Excel 数值序列、日期系统和格式组合表达，不自动给全部数值附加 DateTime 身份。

ExcelIO 继续承担文件读写；需要增强类型读写时，以兼容既有公共 API 的最小扩展或专门适配完成。新编辑器不直接依赖全局静态变更回调。代价是过渡期需要模型转换和夹具，不能凭适配器恢复历史文件已经丢失的类型。

完成条件是类型与日期语义往返、稀疏存储和旧库回归均通过。若 double 无法满足将来的精确财务场景，另行设计显式 Decimal/BigInt 能力与格式版本，不能静默改变现有 Number 语义。

## ADR-003：模块先分边界，再按需要拆程序集

**状态：M1 已建立 Core / Infrastructure 编译边界；后续模块按需要继续拆分。**

采用 Domain、Core、Calculation、Storage、Scripting、ScriptContracts、Desktop 的职责划分。Core 定义端口，具体适配器在启动组合根注入；Worker 只依赖协议和原生适配子模块，不反向引用桌面客户端。

0.2 因 APP-003 的编译约束建立了 `QuickExcel.Infrastructure`：Core 的项目文件不引用 ExcelIO、Formula 或 Scripting；具体存储、计算和运行时工厂由 DesktopComposition 注入。Domain 仍在 Core 程序集内。代价是需要持续检查内部依赖，不能仅以目录名代表隔离。未来模块需要独立复用、测试或分发时，依据实际引用图拆分，不默认每个服务一个程序集。

## ADR-004：文档会话单写入队列，修改通过事务命令

**状态：M1 同步串行写入门禁与内容事务已实现；完整异步队列、结构和动作命令待后续实施。**

每个打开实例有独立 `DocumentSession`。0.2 的单元格编辑/粘贴/清除、新增表和撤销先预检再原子提交；同步锁构成唯一写入门禁，`ExecuteAsync` 不代表已经有专用异步执行队列。计算和 I/O 在写锁外使用不可变快照。完整行列结构命令与脚本动作沿用同一原则，尚未实现。

这让撤销、保存与脚本动作共享一致语义。代价是复制/持久化快照和历史占用内存，需要结构共享或局部快照以及明确预算。不能为减少内存而让后台任务读取正在修改的可变对象。未来若确需协同编辑，应另立操作合并协议；当前单写入规则不能直接假装成为分布式一致性方案。

## ADR-005：统一计算调度器，用修订和代次防止旧结果覆盖

**状态：M1 四元组提交门禁和同表快照适配已实现；M3 完成跨表/增量迁移。**

工作簿级调度器维护跨表依赖，使用类型化求值和增量失效。每个结果关联会话、输入修订、计算代次和脚本代次。取消仅节省资源，结果有效性由提交时核验保证；撤销同样提升修订，不恢复历史修订号。

代价是要维护依赖图、错误状态和可重现调度测试。先做完整重算作为正确性参考，再与增量路径逐次比较。旧 `FormulaEngine` 和新调度器不能同时监听并提交同一文档。动态数组、异步 UDF 和迭代循环计算需要单独设计，不以未定义行为塞进此调度器。

## ADR-006：XLSQ 使用 ZIP 容器，内嵌 XLSX 为内容唯一来源

**状态：已选方向；v1 已存在，v2 在 M2 实施。**

扩展名固定为 `.xlsq`。保留 `workbook.xlsx` 作为单元格、公式、样式、名称和工作表顺序的唯一持久化来源；manifest 与状态文件保存版本、稳定身份、脚本绑定和缓存有效性。脚本存 UTF-8 源码，不保存引擎字节码或有效执行授权。

代价是 XLSX 本身与外层 ZIP 有嵌套开销，且需共同预算。优点是不会出现 JSON 与 XLSX 各有一份单元格内容而无法判断谁是最新的情况。确需超大表随机访问时，再以测量决定新容器版本或可选数据部件，不在 v2 中暗中引入第二份事实来源。具体字段仅以 [格式专题](03-file-format-and-compatibility.md) 为准。

## ADR-007：兼容性按能力声明，导出有快照和可移植公式两种语义

**状态：已选方向；当前仅快照导出，M2/M3 扩展。**

XLSX 是交换格式，不等同于完整 Excel 行为。当前导出公式缓存为值。目标增加保留受支持标准公式的模式，但 JS 函数及其跨表传递依赖必须按导出计划冻结为值；旧缓存需等待重算或由用户明确选择。

未知部件只在可判断未失效时原样保存；存在损失必须说明受影响对象并允许取消或另存。代价是部分复杂 Excel 文件不能无提示编辑保存。若真实用户的常用文件要求更高兼容性，应扩充已验证支持矩阵，而不是通过“兼容 xlsx”措辞跳过测试。

## ADR-008：保留真正 QuickJS，引擎版本固定并追踪来源

**状态：已选方向；当前使用 QuickJS-NG 0.17.0。**

沿用现有 QuickJS-NG native bridge，独立记录源码版本、哈希、构建参数、补丁和许可证。通过运行时门面隔离 P/Invoke，不以另一种 JS 引擎冒充 QuickJS。当前来源见 [native/SOURCES.md](../../QuickExcel.Scripting/native/SOURCES.md)。

代价是 Windows 原生构建、ABI、资源管理和引擎漏洞升级需要持续维护。升级先跑语言/桥接/限制/崩溃/性能回归；引擎字节码不进入 `.xlsq`，避免保存格式与某个引擎二进制版本强绑定。若引擎维护或 ABI 成本不可接受，重新评估实现，但必须明确语言差异与文件迁移要求。

## ADR-009：默认每文档 worker，进程隔离与 OS 访问控制分别验证

**状态：worker 方向已选；OS 机制待 M4 验证、M6 放行。**

独立 worker 允许超时终止和原生崩溃隔离。宿主控制协议、预算、源码授权与结果提交；不接受 worker 请求任意系统操作。每文档运行时串行执行，避免 QuickJS 对象跨线程并发访问。

Job Object 用于进程管理和资源限制，文件/网络访问仍需要独立安全机制。其职责边界依据 [Microsoft Job Objects 文档](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。M4 比较受限令牌与 AppContainer 等策略对 native DLL、运行库、管道和便携分发的影响，最终依据实际发布包的系统调用测试作决策。

代价是进程内存、启动时间与 IPC。可通过按需启动、批量调用和关闭释放控制，但不提前采用共享 worker 池牺牲文档隔离。若 OS 策略未通过门禁，只能发布明确限定可信脚本的试用候选，不算完成 M6 Beta，也不能宣称任意第三方脚本安全。该限制不阻挡用户关闭脚本使用表格本身。

## ADR-010：UDF 显式输入；动作脚本只提出变更

**状态：已选方向；v1 UDF 已有，完整契约 M3/M4 实施。**

UDF 接收显式参数，返回受支持的标量或错误，不直接读写活动工作簿。现有 v1 区域仍是一维参数；二维区域、描述符和命名空间需显式 API 版本选择。不得静默改变已保存脚本的参数形状。

动作脚本由用户运行，在只读快照上产生有界 patch；宿主检查 baseRevision、权限和容量后一次提交。撤销重放已记录的数据，不重跑脚本。代价是作者需要理解函数和动作两类入口，以及冲突时重新运行。

可变闭包和时间/随机输入会破坏 UDF 纯度；禁用部分全局对象不足以证明确定性。M3 先冻结执行契约：含 JS 的工作簿采用每轮重建上下文、稳定顺序完整重算，不复用 UDF 及下游的未变结果。M4 落实 worker 严格策略，经过验证后才能优化 JS 增量路径；确定性等价承诺始终限定已验证子集。网络、异步任务、外部凭据及任意 OS API 均需后续单独设计，不属于首个 Beta。

## ADR-011：保留 DataGrid 直到性能 spike 证明替换必要

**状态：待验证；M5 UI-002 决定。**

当前 WPF DataGrid 可快速验证交互。先建立 `IGridSurface` 隔离选区、编辑、可见区域与绘制，使用固定大表负载测量，再决定继续适配、局部绘制或替换控件。WPF 的 UI 虚拟化与数据虚拟化是两件事，启用控件虚拟化并不能自动避免大量数据对象分配。依据 [Microsoft WPF 控件性能文档](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-controls)。

保留控件降低原型迁移成本；自绘可提升可控性，但增加 IME、无障碍、编辑焦点和高 DPI 工作量。决定依据是 [质量专题](06-quality-performance-and-delivery.md) 的滚动、延迟、内存和可访问测试，不以外观偏好替代验证。更换控件不改变领域与命令契约。

## ADR-012：原子显式保存与恢复草稿分开

**状态：已选方向；基础原子保存已有，M2 接入、M6 完善。**

显式保存从一致快照生成候选文件，在同目录完成写入与校验后替换目标；只有保存的修订被标记为已保存。自动恢复写独立草稿，不能把“用户尚未选择保存”变成静默覆盖原文件。检测外部修改后要求选择处理方式。

恢复记录、文件历史和诊断均可能包含用户数据，默认留在本地并有清理规则；恢复不带入脚本执行授权。代价是需要草稿索引、清理、冲突和故障注入测试。网络盘、同步盘等文件系统的原子性不未经验证就承诺；平台行为边界写入支持矩阵。

## ADR-013：发布模式由干净环境试验决定，保留可追溯构建

**状态：当前 framework-dependent；Beta 分发模式待 M6 决定。**

当前 Windows x64 包依赖 .NET 10 Windows Desktop Runtime。Beta 比较 framework-dependent 的体积与运行时前置条件，以及 self-contained 的体积与运行时更新责任。两者都必须提供完整目录、native DLL、许可证及版本信息，不能只交付单个 EXE 并假设其可运行。

默认不把安装器、自动更新服务或文件关联作为核心正确性的前置要求。若提供安装器，检查卸载不会删除用户文档；若提供更新，先单独定义校验、回退和运行时升级机制。发布候选必须在无 SDK 的干净 Windows 环境实测，编译成功不代替安装验收。

## ADR-014：DOM-001 的值、缓存与日期边界

**状态：M1 首个实施切片已完成；后续 facade/快照/会话接入见 ADR-015。**

在现有 Core 项目的 `QuickExcel.Domain` 命名空间实现不可变值对象，不新增空程序集。`CellValue` 默认值是 Blank；显式构造文本、有限 double、布尔或错误，不提供字符串猜型和隐式转换。非有限 double 产生 `CellErrorCode.Number`；错误代码与诊断文字分开，文本 `#VALUE!` 仍是文本。

`CellContent` 只保存字面量或原始公式及样式编号；公式以 `=` 开头，非空但允许尚不能解析的表达式。`CellCalculation` 单独保存可空缓存、状态、输入修订和两种代次；无缓存和缓存值为 Blank 不同。Fresh 必须有非错误值，Error 必须有错误值；Dirty/Running/Stale/Blocked 可以保留旧值（含旧错误）。版本均为非负数；本切片仅定义元数据，提交门禁仍属 APP-002。

日期仍是 Number，`ExcelSerialDate` 只是显式转换辅助对象。保留原始有限序列值和日期系统；1900 系统的 `[60,61)` 标识虚构闰日，不能转换成真实 `DateTime` 或 1904 日期。日期转换只接受/返回 `DateTimeKind.Unspecified`，不隐式处理时区。负序列按历法延伸：1900 序列 0 对应 1899-12-31、1904 序列 0 对应 1904-01-01；这是 QuickExcel 辅助 API 的明确策略，不承诺 Excel 会显示负日期。超出 .NET 日期范围时转换失败，原数值仍可保留；double 小数日期不承诺 tick 级往返精度。

接近 `DateTime.MaxValue` 的合法日期也可能因 double 舍入越界而被 `FromDateTime` 拒绝，不返回无法转换回日期范围的序列。

两种日期系统和虚构闰日的兼容背景见 [Microsoft 日期系统说明](https://support.microsoft.com/en-gb/excel/date-systems-in-excel)与 [1900 闰年说明](https://learn.microsoft.com/en-us/office/troubleshoot/excel/wrongly-assumes-1900-is-leap-year)。文件类型保真、格式化和日期函数仍由 M2/M3 分别验收。

## ADR-015：0.2 试用版的 M1 落地边界

**状态：2026-10-22 已实现；交付范围是 0.2 可信脚本试用版，不是 M2–M6 完整 Beta。**

用户选择先交付统一会话、事务撤销、可靠保存和回归组成的第一版。沿用 XLSQ v1、DataGrid、旧公式解析器及进程内 QuickJS，同时把这些兼容适配器移出纯 Core，避免一次版本同时扩大文件、公式和运行时隔离承诺。

**编译边界。** [QuickExcel.Core.csproj](../../QuickExcel.Core/QuickExcel.Core.csproj) 仅依赖 .NET，拥有 `QuickExcel.Domain` 不可变类型、命令、`DocumentSession` 和端口。[QuickExcel.Infrastructure.csproj](../../QuickExcel.Infrastructure/QuickExcel.Infrastructure.csproj) 引用 Core、ExcelIO、ExcelIO.Formula 及 QuickExcel.Scripting，承载 `QuickExcel.Storage`、`QuickExcel.Calculation`、`QuickExcel.Runtime`。DesktopComposition 选择并注入具体服务；本次不修改独立 ExcelIO 仓库。

**稀疏快照与唯一写入者。** `WorkbookSnapshot` / `WorksheetSnapshot` 使用不可变集合与稳定 SheetId，远端编辑不展开空矩形；外部样式、图片和旧库对象不得反向修改领域快照。会话通过同步写锁原子替换快照；全部输入事务先验证，任何一格失败都不写入。计算结果也只能通过同一门禁发布，通知在锁外带着对应提交快照发出。不存在另一个可变 XlWorkbook 作为编辑事实来源。

**计算完整身份。** `CalculationStamp` 包含 `SessionId`、`InputRevision`、`CalculationGeneration`、`ScriptGeneration`。提交时四项必须同时等于当前会话且会话未关闭；每个公式缓存的修订/代次和目标也整批验证。成功提交消费计算代次，因此迟到、旧会话、重复或混合代次的结果都不能覆盖现状。撤销推进新 Revision，不倒退输入版本；授权启停只改变执行代次，不使未变化的源码产生 dirty。

**历史与源码。** 默认历史预算为 32 MiB 的估算成本，内容及缓存保持类型、公式与样式。单次操作超过预算先拒绝；累计超限释放最早记录并显示已丢弃记录数。源码使用编辑控件自身历史：源码修改仍推进文档修订并撤销脚本授权，但保留单元格 undo/redo。单元格历史恢复时保留当前源码，不恢复旧授权，也不重跑历史脚本。结构命令当前只交付新增表，完整行列插删/引用重写留待后续。

**计算和运行时兼容路径。** 同表稀疏 AST 求值与完整重算保持原型函数范围；真实错误按类型传播，错误形状文本保持 Text，JS null 返回 Blank。每轮已授权计算创建、加载并释放独立 QuickJS 上下文，按稳定顺序调用；跨表和禁用函数及下游保持 Blocked 缓存。v1 JS 范围为包含空位置的一维行主序数组，最多 1,000,000 个位置；元素反映当前数字/文本/布尔类型，Blank 输入仍为 `""`。整轮 5 秒预算或取消导致本轮不提交；原生单次调用仍依靠约 1 秒中断期限，取消令牌不能抢占正在执行的 native 调用。

**保存边界。** `WorkbookDocument` 串行捕获保存快照并交给存储端口；同目录临时写入、容量检查和刷新后原子替换成功，才标记该快照修订已保存。保存 R 时出现 R+1，R+1 仍为 dirty；失败不破坏旧文件。导出独立值快照，不修改原文档、不推进 SavedRevision。旧库稠密转换预检累计占位行/格预算，因此内存可稀疏编辑并不保证任意跨度可存入旧格式。

**保留的明确限制。** v1 字面量写为文本，重开不猜测恢复类型，空白/空文本及公式缓存类型仍可能损失；SheetId 和缓存新鲜度不跨 v1 文件保留。导入不恢复来源日期系统，按 Windows1900 接入；保存/导出 Mac1904 快照明确拒绝，不能称为完整 1904 导入拒绝或日期保真。旧公式解析器、数字文本转换、日期函数文本结果和静态全分支依赖图仍有限制。没有 ScriptWorker、IPC、OS 隔离、动作脚本、v2 格式、自动恢复或外部文件冲突检测；原生崩溃仍可能影响桌面进程。

M1 证据由 [快照测试](../../QuickExcel.Core.Test/WorkbookSnapshotTests.cs)、[会话测试](../../QuickExcel.Core.Test/DocumentSessionTests.cs)、[适配计算测试](../../QuickExcel.Core.Test/CalculationAdapterTests.cs)、[存储适配测试](../../QuickExcel.Core.Test/StorageAdapterTests.cs)、[facade 测试](../../QuickExcel.Core.Test/WorkbookFacadeTests.cs) 及现有 WPF/native smoke 共同提供。实际放行结果以 [实施记录](08-baseline-and-progress.md) 为准；这些测试不替代 M5 大表/IME/无障碍或 M6 净环境及安全验收。

## 决策维护

每项变更追加新的结论与依据，保留旧取舍的简短记录。先变更契约再变更实现，涉及文件或脚本 API 的不兼容变更必须关联版本策略和迁移测试。尚未验证的选择保留状态、负责人角色和截止里程碑，不能在发布文案中变成已经交付的保证。

## ADR-017：M2 存储实现边界（2026-10-27）

新增独立的类型化 XLSX/XLSQ v2 存储适配器，保持 Core 无 ExcelIO 依赖，不修改同级 ExcelIO 源码。旧适配器与其 v1 回归继续保留。单元格类型、公式、缓存、数字格式及日期系统只写入 workbook.xlsx；document.json 仅保存身份、修订及脚本绑定。

读取 v1 不按文本外观恢复已经丢失的类型；迁移保存必须写入其他路径。v2 严格校验版本、能力、摘要及身份绑定。所有读取共享解压/解析预算，可取消，不执行脚本。新文件先写同目录临时文件，重开校验后才替换目标。

支持子集外的部件或 XML 属性进入兼容性清单。未经工作簿内容修改可保留原 XLSX 字节；修改后不能证明安全的特性阻止普通保存，只有显式另存受支持副本才能移除。当前结果导出拒绝缺失缓存；过期缓存需显式选择。脚本模块可以持久化，但多模块执行留待 M4，不能把模块源码串接后冒充模块执行。

## ADR-018：M3 类型化计算与保守复用（2026-10-27）

Core 提供自己的有界 A1 AST、名称与结构变换，Infrastructure 负责类型化求值和稀疏依赖图。旧 ExcelIO 解析器无法保留带引号的表名、数字表名和全部绝对引用，旧函数的字符串强制转换也不适合新模型，因此保留旧适配/测试，另建已声明支持子集的求值器，不修改同级库。Core 继续无外部项目依赖。

新计算器仅复用同会话、相同语义上下文的完整成功结果，根据输入内容差异与新依赖闭包选择求值；结构/名称/日期/脚本代次变化全量失效。图仍每轮重建，不把这个阶段描述成索引维护零成本。取消、超时和注册冲突不提交半批结果。静态全分支依赖与懒求值分开，循环和阻塞按保守依赖图处理。

M3 描述符 apiVersion 是函数参数桥版本；v2 明确选择二维形状和 null Blank，文件 scriptApiVersion 1 继续描述既有单模块加载 API。此处澄清早期拟议将两者共用版本的说法。源码保存时不执行、不推断注册表；旧应用可读取源码但不能执行对象描述符。v1 注册仍解析，但 M3 禁止覆盖内置名称；错误明确提示用户迁移到 JS 命名空间，不自动改源码。strict 未实现且明确拒绝。

结构剪切/行列变换通过统一命令原子提交，无法表达的非连续引用或图片/合并移动先拒绝。导出以相同绑定图识别跨表传递依赖，冻结不可移植闭包，保留并展开独立标准公式；缓存状态不等于跨会话授权。支持矩阵、语义差异和证据统一见 10-m3-calculation.md。

## ADR-019：M4 首切片的 worker 生命周期与发布边界（2026-10-27）

新增只依赖 BCL 的 ScriptContracts 和独立 ScriptWorker，Desktop 通过 Infrastructure 客户端调用。首切片每轮创建一个专用进程，不跨轮驻留，保留 M3 上下文重建与完整重算策略；启动成本先接受，合批和常驻调度在测量后推进。协议允许 256 次调用的批次，当前计算器仍按单调用发送。

单进程只接受一个在途请求，不保留排队请求；拒绝并发作为初始反压策略。宿主控制整个执行期限，取消直接终止进程，编辑/授权变化与会话关闭同时使请求失效。完整六元组校验之外继续保留 Core 提交门禁，任何 transport/lifecycle 故障不转成可被 IFERROR 吞掉的单格错误。没有自动重试或进程内回退。

Windows Job 提供关闭清理、进程数及提交内存上限，配置失败拒绝发送脚本。它不提供文件或网络访问拒绝。本轮不宣称 SEC-001 完成，受限令牌/AppContainer、最小句柄继承与系统调用探测留给后续 M4；M6 OS 门禁保持未通过。模块、动作持久化和 patch 提交同样尚未完成。详细预算、实际测试与余项见 [M4 记录](11-m4-worker.md)。
